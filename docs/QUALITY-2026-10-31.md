# Eidos 科研质量复核与改进

日期：2026-10-31。当前案例：[A Fix for Softmax and Cross-Entropy, v3](https://arxiv.org/html/2610.31642v3)。

## 结论与验收边界

原有“测试绿、页面可打开、论文函数可调用”不足以支持完整科研质量结论。本次以 Softmax Collapse / Cancellation 为对抗性验收案例，复用已有 Paper2Agent 转换，贯通数值复现、独立参考、负对照、工具调用、网站和三格式报告。论文发现归原作者；Eidos 的交付是复现、验证和复用能力。

科学证据来自 `site/reports/numerics/evidence.json`、`docs/NUMERICS.json`、已有 Agent 的 `reference/barron2026_agent/docs/evidence.json` 与调用轨迹。全局运行基线来自 `docs/SELF_AUDIT.json`，具体覆盖范围必须读取记录，不能把 SKIP 解释成 PASS。

## 反思：把能力不足转化为可检验的失效机制

| 发现的问题 | 影响 | 已落地修复与反证 |
|---|---|---|
| 将指数溢出、前向舍入与论文的梯度机制混称 | 错误理解论文，修复无法针对真正问题 | 区分两种梯度机制；独立 Decimal 定义同时检查 loss 和梯度 |
| 绝对误差下限掩盖极小梯度损坏 | target 梯度丢失仍可能被判通过 | 相对分量/向量误差与相对零和残差；丢失 target、平稳点噪声两个故意错误对照必须被拒绝 |
| 先把高精度参考转为 float64 再计算误差 | 将小的真实误差显示成 0 | 在 Decimal 内计算 L2 误差后才转换显示值；1/3 回归用例约束此行为 |
| 返回低精度结果可以放宽验收阈值 | 后端偷偷降精度仍可能通过 | 要求梯度 dtype 与输入一致，降精度返回 ERROR |
| 只验证论文的一个数和梯度和 | 无法证明 Cancellation 被解决 | 原有 MCP 四工具保留，7 个真实调用案例；加入 teacher logits、相等/近相等/远离分支验证 |
| 自审忽略 pytest 失败退出码 | 失败可能被写成健康基线 | 测试执行、收集、链路、有效性门均按退出码拒绝；失败不覆盖记录 |
| 热更新失败后回退到启动时模块 | 运行代码与已接受更新不一致 | 原子候选模块，失败保留最后接受版本；连续更新/失败回归测试 |
| watchdog 故障路径缺少 import、单实例依赖 PID 文件 | 故障时恢复失效或重复启动 | 故障路径测试、进程生命期 OS 文件锁；受控子进程终止后实测恢复 |
| 跨盘注册/YAML 路径、旧脚本 TODO 退出 0 | onboarding 看似成功却不能使用 | 统一安全 Python 入口、结构化 YAML、拒绝覆盖；真实 Bash 隔离测试 |
| CI 环境与锁漂移 | 本机绿不能代表干净安装 | 固定工具版本，检查锁并 locked sync；干净独立环境验证交付包；声明 Python >=3.11 |

## 自进化已形成的闭环

论文失效机制 → 独立可证伪检查 → 负对照 → 可复用 NumPy / 可选 Torch 实现 → 原有 MCP / Agent → CI 数值审计 → 同源数据、报告与复现包。

运行 `python tools/audit_numerics.py --projects` 会执行内置 12 项数值资格检查和两个负对照，并扫描声明 `numerics: required` 的消费者。静态扫描只是启发式，语法/编码错误会报告不可扫描，不会当作干净。

这不意味着任意消费者已经安全。使用 JAX、Torch、AMP、其他融合算子的项目必须将实际执行的后端适配到 `probe_hard_cross_entropy` / `probe_logit_distillation`，记录 dtype、设备、版本和输入；不能拿 NumPy 的 PASS 替代其验收。现有 Torch 验证支持有限 float32/float64 的一阶梯度，包含本机 CUDA 检查。

## 尚未取得的证据与下一步

1. **完整论文训练结果**：已完成三种子、2,000 步的适配平稳点训练对照，仍未复现论文 grokking、泛化或大模型训练收益。教师训练准确率 100%、held-out 约 0–0.0712%，故只支持平稳点机制结论；下一步须使用具备泛化能力的教师及原论文任务。
2. **所有后端的数值安全**：未覆盖 bfloat16、AMP、二阶求导。每种后端须有独立参考和负对照；无资格检查时保持 UNQUALIFIED。
3. **长期可用性**：24 小时只读观察已启动，结果在 `.scratch/quality/soak-24h.json`；运行中为 RUNNING，未完成不算 PASS。受控进程恢复不等于整机登录重启验收。
4. **远端 CI**：工作流已修改并做本地检查；按用户要求同步 GitHub，远端运行结果须单独核对，不能从本地通过推断。
5. **科学新颖性**：下一研究问题必须有文献对照、可证伪假设和足以区分解释的实验；复现现有方法本身不能写成新发现。
