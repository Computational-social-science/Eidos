# EIDOS Agent 0.5.0 compatibility preview

This preview adds a project-local CLI, read-only worker observations and a guarded
software incident ledger. It retains distribution `eidos` and namespace
`framework`, and adds the `eidos-agent` console alias alongside `eidos`.
The public-index distribution/import migration remains separate; install the
verified GitHub wheel rather than the unrelated PyPI `eidos` package.

The default path uses local/free resources and needs neither Gemini nor a paid
model API. A worker installation does not install or migrate a resident central
controller, restart services or qualify a model as a scientific reasoner.

its evaluator, fixture, original owner and wheel identities before candidate
evaluation. It executes the original `audit_inference` owner under the triggering
inherited-pipe input, alongside lower-level and unaffected controls. Unentered
timeouts cannot count as reproduced failures. A deliberate unchanged-SDK candidate
is rejected; physical pin reversion preserves nonempty actual run history.

Preparation reaches VALIDATED and refuses premature closure. Actual publication,
CI/tag/asset fetching, originating-project adoption, failed-replay reversion and
fresh successful replay are executed only after the release exists. Their final
result is a separate post-publication receipt; these notes do not predeclare it.

The incident ledger verifies local receipt integrity. The deterministic producer
executes its protected oracle and fetches real public GitHub records; hashes alone
do not establish arbitrary evaluator honesty, scientific novelty or scientific RSI.
